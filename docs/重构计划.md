# PHP 博客重构计划（Flask → PHP + MySQL，1:1 移植）

> 依据：对 `d:\blog`（Flask 单文件应用 app.py，6814 行）的全面分析。
> 目标：在 `PHP_blog/` 下用 PHP 8.3 + MySQL 重构，前后台分离、动静分区、多主题、插件可扩展，
> 1:1 保留 admin 后台 UI 与前台 tech 主题的全部 HTML/CSS/JS 交互。

## 二、目标架构

### 2.1 目录结构（Typecho 风格）

```
PHP_blog/
├── public/                  # ★ Web 根（动静分区：只放入口与静态资源）
│   ├── index.php            #   前台入口（Front 控制器）
│   ├── admin.php            #   后台入口（Admin 控制器，前后台代码分离）
│   ├── router.php           #   php -S 内置服务器路由（/admin→admin.php、静态直出+白名单）
│   ├── .htaccess            #   Apache 重写（部署用）
│   ├── static/              #   静态资源（原 /static 原样拷贝：css/js/images/icons/vendor）
│   └── themes/tech/         #   主题静态（theme.css / theme.js / preview.png，扩展名白名单）
├── core/                    # ★ 应用核心（不在 Web 根，无法被直接访问）
│   ├── bootstrap.php        #   自动加载、配置、异常、安全头
│   ├── App.php  Router.php  Request.php  Response.php
│   ├── Db.php               #   PDO MySQL 封装（预处理、事务）
│   ├── View.php             #   模板引擎（Jinja2 兼容子集，见 §5）
│   ├── Session.php Auth.php Totp.php   #   会话/登录/OTP（兼容 werkzeug pbkdf2）
│   ├── Theme.php            #   主题解析（info.json、active_theme、静态白名单）
│   ├── Hook.php  Plugin.php #   插件钩子（Typecho 风格）
│   ├── controller/front/    #   前台控制器（Home/Post/Project/Link/About/Status/Search/Feed/Comment/Avatar）
│   ├── controller/admin/    #   后台控制器（Dashboard/Post/Category/Project/Link/Comment/Upload/Theme/Setting/Export/Upgrade/Status/Orphan/Auth/Timeline…）
│   ├── service/             #   Markdown、Comment、Mail、Upload、Watermark、Thumb、
│   │                        #   GithubSync、Monitor、IpRegion、Export、Upgrade、Search、Feed
│   └── lib/                 #   轻量 SMTP 客户端、ip2region xdb 检索器（Python 版移植）等
├── themes/
│   └── tech/                # ★ 默认主题：模板 1:1（Jinja 语法原样拷贝）+ info.json
├── plugins/                 # 插件目录（每插件：plugin.json + Plugin.php + hooks）
├── storage/                 # 运行数据（非 Web 根，经路由代理输出，与原站 URL 一致）
│   ├── uploads/             #   上传（/uploads/<path> 路由输出，.originals 禁直出）
│   ├── share_thumbs/        #   分享缩略图缓存（/share-thumb/<path>）
│   ├── cache/  logs/  backups/  session/
│   └── .secret_key          #   会话密钥（沿用原生成逻辑）
├── config/config.php        # DB 连接（<db-host>/<db-name>）、站点常量
├── bin/                     # CLI：migrate.php（SQLite→MySQL）、monitor.php（守护）、worker.php
├── vendor/                  # 第三方（league/commonmark 等，若引入）
└── docs/重构计划.md
```

**动静分区**：静态文件（/static/*、/themes/*）由 Web 服务器直接响应；动态请求进双入口。
**前后台分离**：`index.php` 只挂前台路由，`admin.php` 只挂 `/admin/*`，控制器目录物理隔离。
**多主题**：`themes/<name>/{info.json, *.html, theme.css, theme.js, preview.png}`；
激活主题读 settings.`active_theme`（默认 tech）；模板查找序：激活主题 → 该主题缺省回退（原 ThemeLoader 语义）。
**插件扩展**：`Hook::on('钩子名', ...)` / `Hook::emit('钩子名', $payload)`；插件在 bootstrap 扫描
`plugins/*/plugin.json` → require Plugin.php → `registerHooks()`。预留钩子位：
`posts.query` `post.render` `comment.create` `comment.beforeShow` `page.header` `page.footer`
`admin.menu` `admin.dashboard` `upload.after` `setting.save`。

### 2.2 请求流程

```
浏览器 ── /static|/themes ──→ Web 服务器直接出静态（动静分区）
      ── /admin/*        ──→ public/admin.php → Admin 路由 → Auth(O session/OTP/锁) → Admin 控制器 → View(模板)
      ── 其余            ──→ public/index.php → Front 路由 → 控制器 → Service → View(激活主题模板)
```

## 三、数据库设计与数据迁移

### 3.1 MySQL 表（utf8mb4_unicode_ci，与 SQLite 结构一一对应）

| 表 | 关键列（在 SQLite 基础上定型） |
|---|---|
| posts | id AI_PK, title, slug UNIQUE, content MEDIUMTEXT, excerpt, tags JSON('[]'), cover, read_time, views, status, is_featured, category_id, created_at, updated_at |
| settings | `key` PK varchar(128), value MEDIUMTEXT |
| users | id, username UNIQUE, password_hash（保留 werkzeug 格式，PHP 端兼容校验） |
| projects | id, name, description, url, stars, language, topics, sort_order, featured, github_repo, custom_name, created_at |
| links | id, name, url, description, avatar, sort_order, status, created_at |
| comments | id, post_id NULL, project_id NULL, parent_id NULL, author, email_hash, website, content, status, is_private, ip, ip_location, agent, created_at |
| timeline | id, date, content, sort_order, created_at |
| memories | id, title, text, image, date, sort_order, created_at |
| categories | id, name, slug UNIQUE, sort_order, created_at |
| service_checks | id, service_id, checked_at DOUBLE, ok, latency_ms, cert_days, detail + INDEX(service_id, checked_at) |

（posts 其余列以 `SELECT *` 实际探测 + `db_*` 函数引用为准，迁移脚本自动对齐。）

### 3.2 迁移

`bin/migrate.php`（CLI，PDO sqlite 读 + PDO mysql 写）：
1. 建表（CREATE TABLE IF NOT EXISTS）
2. 逐表搬迁数据（47 文章、59 settings、14 评论等；tags JSON 原样；timestamp 保持字符串原值）
3. 灌入 settings 默认值（原 `_DEFAULT_SETTINGS` 56 键，缺省补底）
4. 输出校验：各表 COUNT 对比 SQLite

### 3.3 连接配置

`config/config.php`：host=&lt;db-host&gt;, db=&lt;db-name&gt;, user=&lt;db-user&gt;, pass=&lt;db-password&gt;, charset=utf8mb4。

## 五、模板移植策略（1:1 的关键）

**决策：自研 Jinja2 兼容子集 PHP 模板引擎，模板文件原样拷贝、零语法改写**，保证 HTML 结构零漂移。

- 编译型：Jinja → PHP（缓存到 `storage/cache/templates/`，mtime 失效）
- 支持语法（按 52 个模板实际用法枚举后实现）：
  - `{{ expr }}` 自动转义（`|safe` 关闭）；`{% if/elif/else %}`、`{% for/else %}`（loop.index/first/last/length）、`{% set %}`、`{% raw %}`
  - `{% extends %}` + `{% block %}` 继承（base→子页）、`{% include %}`（共享 `_footer_text/_comments/_macros`）
  - 过滤器：`safe e length upper lower replace join default urlencode nlbr truncate selectattr equalto list first last attr sort …`（以实际清单为准）
  - 表达式：`and/or/not/==/!=/>/</in/is not/三元 a if c else b`、属性访问 `a.b`、下标 `a['b']`、函数调用
- 全局函数/变量（对应 `inject_globals` context_processor + `jinja_env.globals`）：
  `url_for()`（static/theme_static/各端点/rss_feed/posts_page/index）、`icon()`、`blog_name`、`nav_on/nav_pages/nav_all`、`all_tags`、`links`、`active_theme`、`version`、`now_year` 等 40+ 项，由 `View::shareGlobal()` 统一注入
- 拷贝范围：admin 23 模板 + tech 17 模板 + 共享 3 模板；`static/` 与主题静态**原样复制**，不改一行 CSS/JS

## 六、服务层移植清单（难点对策）

| 服务 | 方案 |
|---|---|
| Markdown | league/commonmark + Table/TaskList/Footnote/Autolink/DescriptionList/Attributes/HeadingPermalink/Strikethrough 扩展；后处理沿用原 Python 逻辑（图片 lazy/尺寸注入、链接 target/rel/`javascript:` 过滤、front-matter 剥离、自动链接归一）→ 输出结构与原站一致 |
| 密码 | 兼容校验 `pbkdf2:sha256:260000$salt$hash`（hash_pbkdf2 + hash_equals），现有管理员密码直接可用 |
| 会话 | PHP session：cookie 参数与原站一致（SAMESITE=Lax/HTTPONLY/3600s），存储 `storage/session/` |
| OTP | PHP 实现 RFC6238（hash_hmac sha1 + Base32），与 pyotp 互通；紧急码清除/恢复流程同原 |
| 邮件 | 自写轻量 SMTP 客户端（465=SSL / 否则 STARTTLS，与 `_smtp_send` 同逻辑），通知/忘记密码/测试邮件三处共用 |
| ip2region | 移植 `vendor/ip2region/searcher.py` 为 `core/lib/IpRegion.php`（xdb v2 向量索引 + 二分），复用原 xdb 文件 |
| 头像代理 | Curl 多源（Cravatar d=404 → QQ）+ 本地缓存，URL 规则同原站 |
| 水印/缩略图 | GD 重写（Pillow 逻辑对照）：水印开关/文案/位置/字号、变更触发全站重做；share-thumb 4:3 800×600 |
| GitHub 同步 | curl 异步化：请求内 `start /b php bin/worker.php sync …` 后台进程 + `storage/data/project_sync_state.json` 轮询（原线程语义，页面即时返回） |
| 状态监控 | `bin/monitor.php` 守护（pid 文件，admin 引导时自动拉起），300s 循环写 service_checks（每服务裁 2000 条） |
| 升级/导出 | curl 双源（GitHub→Gitee）；JSON/Markdown/ZIP(zip 扩展)/db-backup 导出下载删除 |
| 安全头 | `_security_headers` 逐条同原（CSP unsafe-inline+https:） |
| flash 消息 | Session 一次性 flash（原 `flash()/get_flashed_messages` 语义） |

## 八、明确不做 / 边界

- `default` 主题不移植（用户指定）
- 不新增原站没有的机制（如 CSRF token），防 1:1 交互偏移
- 不改 URL、不改静态资源文件名与内容、不改模板 HTML 结构
- 项目记忆中 Koa/Express 相关条目与本项目无关，不采纳
